Ontology 架构的底层设计理念The foundational ideas behind the Ontology architecture

定义与实例分离Definition vs Instance

Ontology 定义数据的形状（Schema），实例承载实际内容（Data）。两者独立存储、独立版本化。 Ontology defines the shape (schema) of data. Instances hold the actual content. They are stored and versioned independently.

逻辑与物理分离Logical vs Physical

业务概念（如"航班"、"登机口"）存在于逻辑模型中，物理存储位置（Iceberg、PostgreSQL）通过 AssetMapping 独立配置。 Business concepts (e.g. "Flight", "Gate") live in the logical model. Physical storage (Iceberg, PostgreSQL) is configured separately via AssetMapping.

图模型思维Graph Thinking

所有实体都是图中的节点，实体间的关联都是边，支持级联更新、依赖校验与影响分析。 Every entity is a node. Every relationship is an edge. This enables cascading updates, dependency checks, and impact analysis.

核心构件Core Building Blocks

六大实体类型The 6 Entity Types

每个 Ontology 都由以下六种定义组成Every Ontology is composed of these six types of definitions

ri.shprop.*

SharedPropertyType

全局可复用的属性模板。定义数据类型、校验规则、UI 组件与合规要求。被多个 ObjectType 共享使用。 A reusable property template shared across multiple object types. Defines data type, validation, UI widget, and compliance.

机场示例：共享属性 iata_code (STRING) 被 Airport、Airline 等多个对象复用。 Airport example: Shared iata_code (STRING) reused by Airport, Airline, and other objects.
ri.prop.*

PropertyType

依附于特定 ObjectType 或 LinkType 的具体属性。可继承 SharedPropertyType，支持物理列或虚拟表达式。 A concrete property belonging to a specific ObjectType or LinkType. Can inherit from a SharedPropertyType.

机场示例：Flight 对象上的 flight_iata_code，继承自共享的 iata_code。 Airport example: flight_iata_code on Flight object, inheriting from shared iata_code.
ri.iface.*

InterfaceType

定义契约，规定实现者必须满足的属性与关系要求。支持接口继承。分为对象接口与关系接口两种。 A contract defining required properties and links. Supports interface inheritance. Comes in Object Interface & Link Interface.

机场示例：schedulable 接口要求实现者必须包含 scheduled_time 和 actual_time 属性。 Airport example: schedulable interface requires scheduled_time and actual_time properties.
ri.obj.*

ObjectType

定义业务对象。包含属性集合、实现接口、指定主键，通过 AssetMapping 映射到物理存储。 Defines a business object. Contains properties, implements interfaces, specifies primary keys, maps to storage.

机场示例：Flight 对象，包含航班号、出发时间、状态等属性。 Airport example: Flight object with flight number, departure time, status, etc.
ri.link.*

LinkType

定义对象之间的关系。有源/目标端点、基数（1:1、1:N、M:N），可以携带自身属性。 Defines a relationship between objects. Has source/target endpoints, cardinality (1:1, 1:N, M:N), and can carry properties.

机场示例：flight_assigned_to_gate 将 Flight 连接到 Gate（1:N），携带 assigned_time 属性。 Airport example: flight_assigned_to_gate links Flight to Gate (1:N), with assigned_time property.
ri.action.*

ActionType

定义可执行的操作。指定参数、执行引擎（CRUD、Python、SQL、Webhook）、安全级别与副作用。 Defines an operation. Specifies parameters, execution engine (CRUD, Python, SQL, Webhook), safety level, and side effects.

机场示例：delay_flight 操作，接收 Flight 实例和新时间，安全级别为非幂等。 Airport example: delay_flight action takes a Flight instance and new time, safety level: non-idempotent.

建模方法论Modeling Methodology

七阶段建模流程7-Phase Modeling Process

从数据库 Schema 到完整 Ontology 的标准化路径A standardized path from database schema to a complete Ontology

1

源头发现 (Source Discovery)Source Discovery

连接数据库或读取 DDL 文件，盘点所有表和 Schema，评估复杂度。可选地读取 PDF 业务文档获取领域上下文。Connect to the database or read DDL files. Inventory all tables and schemas, assess complexity. Optionally read PDF business documents for domain context.

2

Schema 提取 (Schema Extraction)Schema Extraction

提取每张表的列定义、主键、外键、唯一约束和 CHECK 约束。输出结构化摘要供人工确认。Extract column definitions, primary keys, foreign keys, unique constraints, and CHECK constraints for every table. Output a structured summary for review.

3

实体分类 (Entity Classification)Entity Classification

将每张表分类为 ObjectType（业务实体）、LinkType（关联关系表）或 Skip（系统表）。Classify each table as ObjectType (business entity), LinkType (junction/relationship table), or Skip (system table).

  • ObjectType：有自己的主键、代表业务实体、有实质性非 FK 列ObjectType: has own PK, represents a business entity, has substantive non-FK columns
  • LinkType：两个 FK 列组成主键的关联表，非 FK 列 ≤ 3LinkType: junction table with 2 FK columns as PK, ≤ 3 non-FK columns
4

共享属性与接口推断 (SharedPropertyType & InterfaceType Inference)SharedPropertyType & InterfaceType Inference

扫描所有实体，发现在 3+ 张表中出现的同名同类型列，提炼为 SharedPropertyType。将相关的共享属性组合为 InterfaceType（如 auditable、locatable）。Scan all entities for columns appearing in 3+ tables with the same name and type. Extract them as SharedPropertyTypes. Group related ones into InterfaceTypes (e.g. auditable, locatable).

5

命名与 RID 生成 (Naming & RID Generation)Naming & RID Generation

按 snake_case 规范生成 api_name，按 ri.{prefix}.{uuid} 格式生成全局唯一 RID，结合业务文档生成 display_name。Generate api_name in snake_case, create globally unique RIDs as ri.{prefix}.{uuid}, derive display_name from business glossary.

6

详细映射 (Detailed Mapping)Detailed Mapping

将 SQL 类型映射到 Proto DataType，推断校验规则（NOT NULL → NotNullRule、CHECK → RangeRule/EnumRule）、UI Widget 和合规配置。配置 AssetMapping 和主键。Map SQL types to Proto DataType, infer validation rules (NOT NULL, CHECK constraints), UI widgets, and compliance config. Configure AssetMapping and primary keys.

7

JSON 生成与校验 (JSON Generation & Validation)JSON Generation & Validation

输出符合 Proto3 JSON 序列化规范的 OntologyRegistry 文件。运行 8 项交叉引用校验，确保所有 RID 引用、api_name 规范、接口契约都正确无误。Output a Proto3-compliant OntologyRegistry JSON file. Run 8 cross-reference validation checks ensuring all RID references, api_name rules, and interface contracts are correct.
